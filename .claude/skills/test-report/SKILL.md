# テスト結果レポート

`mvn test`の実行結果(JUnitのテスト結果とCheckstyleの静的解析結果)を確認し、正常/異常に応じて報告内容を出し分けるスキル。

## 実行手順

1. Agentツールで`test-runner`サブエージェント(`subagent_type: "test-runner"`)を呼び出し、`mvn test`の実行を依頼する。
   - プロンプト例: 「mvn testを実行し、テスト結果サマリーを返してください」
   - このサブエージェントはJUnitの全体件数/OK件数/NG件数、Checkstyleの違反件数のみを返す。個別の失敗内容や違反詳細は返さず、詳細ログを`target/test-results/mvn-test-output.log`に保存する。
2. サブエージェントから返ってきたサマリーを確認し、以下のいずれかに分岐する。

### 分岐A: 全て正常な場合

JUnitのNG件数が0件、かつCheckstyleの違反件数が0件の場合。

- 詳細ログを読み込む必要はない。
- ユーザーには「テストは全て正常に完了しました(全体件数/OK件数、Checkstyle違反0件)」という旨を簡潔に報告する。

### 分岐B: NGが1件以上ある場合

JUnitのNG件数、またはCheckstyleの違反件数のいずれかが1件以上の場合。

1. サブエージェントの返却に記載されている詳細ログパス(`target/test-results/mvn-test-output.log`)をReadツールで読み込む。
2. ログから以下を抽出する。
   - JUnitのNGがある場合: 失敗したテストクラス・テストメソッド名、失敗理由(アサーション内容や例外のスタックトレース)。
   - Checkstyleの違反がある場合: ファイル名、行番号、ルール名、メッセージ。
3. 必要に応じて該当のソースファイル(テストコード・プロダクトコード)をReadツールで実際に確認し、NGの原因を具体的に特定する。
   - `.claude/rules/testing.md`(テスト種別・カバレッジ観点)、`.claude/rules/javadoc.md`、`.claude/rules/error-handling.md`のプロジェクトルールを踏まえて、修正方針が整合するようにする。
4. 以下の形式の表でユーザーに報告する(日本語)。

| 種別 | ファイル名 | NG内容 | 修正方針 |
|---|---|---|---|
| JUnit / Checkstyle | 該当ファイルのパス | 失敗理由・違反ルールとメッセージ | 具体的な修正案 |

- JUnitとCheckstyleの両方でNGがある場合は、1つの表にまとめ「種別」列で区別する。
- 表の前に、JUnit全体件数/OK件数/NG件数とCheckstyle違反件数のサマリーを1行程度で添える。

## 注意事項

- このスキルはテストの実行と結果の調査・報告のみを行う。コードの修正は行わない(ユーザーから別途修正の依頼があった場合のみ対応する)。
- `mvn test`自体の実行は必ず`test-runner`サブエージェントに委任し、メインエージェント側で直接`mvn test`を実行しない(詳細ログの読み込みが必要になった場合のみ、メインエージェント側でログファイルをReadする)。
