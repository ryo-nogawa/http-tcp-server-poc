# Todoリスト生成

実装方針を作業工程単位に分解し、`implementer`サブエージェントが忠実に実装できる粒度のTodoリストをMarkdownファイルとして出力するスキル。

## 出力先とファイル名

- 出力先: `.claude/todo/`（Git管理外）
- ファイル名: `issue-{Issue番号}.md`
  - Issue番号がない場合: `{YYYYMMDD}-{英語ケバブケースの概要}.md`
- 同じIssueのファイルが既に存在する場合は、Readツールで読み込み、**チェック済み（`- [x]`）の項目を維持したまま**未完了項目を更新する。完了済み項目を未完了に戻さない。

## 実行手順

1. Readツールで`.claude/skills/create-todo/todo-template.md`を読み込み、フォーマットとHTMLコメントの指示（記載量の上限）を確認する。
2. 改修内容を把握する。
   - Issueが存在する場合は`gh issue view {Issue番号}`で背景・改修内容・完了条件を確認する。
   - Read/Grep/Globツールで既存のパッケージ構成・類似クラスの実装を調査し、対象ファイルのパスを具体的に特定する。推測でパスを書かない。
3. 改修内容を作業工程単位に分解する（分解方針は後述）。
4. 各工程に「対象ファイル」と「方針」を記載する。
5. Writeツールで`.claude/todo/`配下にファイルを出力する。全項目は未チェック（`- [ ]`）の状態で生成する。
6. 出力したファイルパスと工程一覧をユーザーに報告する。

## 工程の分解方針

該当するもののみを、上から順に実行できる依存順で並べる。工程数は**5項目以内**を目安とする。

| 工程 | 内容 |
| --- | --- |
| プロダクトコード実装 | ドメインモデル・サービス・コントローラなど本体の実装 |
| 設定値の追加 | ポート番号・タイムアウト値などを`src/main/resources/META-INF/spring/application.properties`へ追加 |
| 単体テスト作成 | 対象クラス単位のテスト（`.claude/rules/testing.md`準拠） |
| 結合テスト作成 | `Integration`フォルダ配下にプロトコル（HTTP / TCP Socket）ごとに作成 |
| ドキュメント更新 | READMEなど既存ドキュメントの修正 |

- 1工程 = 1チェックボックスとする。チェックボックスをネストさせない。
- 1工程が大きすぎる場合（対象ファイルが5つを超えるなど）は、機能単位で工程を分割する。

## 記載ルール

- テンプレートのフォーマット（ヘッダの表、`## Todo`、チェックボックスの構造）を変更しない。
- テンプレート内のHTMLコメント（`<!-- -->`）は、指示を読み取った上で**ファイルには含めない**。
- **対象**: リポジトリルートからの相対パスをバッククォートで囲んで記載する。複数ある場合は改行して列挙する。
- **方針**: 何をどう実装するかを1〜2行で記載する。`implementer`はコンテキストを引き継がないため、Todoの記載だけで判断できる具体性を持たせる。
- 文章量は最低限に留める。冗長な前置き・補足説明・所感は書かない。

## チェックボックスの更新

- 生成時は全項目を`- [ ]`とする。
- 実装中の更新（`- [ ]` → `- [x]`）は`implementer`サブエージェントが行う。メインエージェントは`implementer`を呼び出す際、**Todoファイルのパスを必ず伝える**こと。
- メインエージェントはチェックボックスを直接編集しない。進捗はファイルの内容で確認する。

## 注意事項

- このスキルはTodoリストの生成のみを行う。実装には進まない（開発フロー全体は`.claude/rules/development-flow.md`を参照）。
- `.claude/todo/`配下は作業用の一時ファイルであり、Git管理外（`.gitignore`に登録済み）。コミット対象に含めない。
