# Issue作成

改修内容を`.github/ISSUE_TEMPLATE/issue.md`のフォーマットに沿って起票するスキル。

## 実行手順

1. Readツールで`.github/ISSUE_TEMPLATE/issue.md`を読み込み、セクション構成とHTMLコメントの指示（記載量の上限）を確認する。
2. ユーザーの指示内容から「背景」「改修内容」「完了条件」を整理する。
   - 指示から読み取れない項目がある場合のみ、ユーザーに確認する。推測で埋めない。
   - 関連する既存コードを確認する必要がある場合は、Read/Grep/Globツールで調査してから整理する。
3. タイトルとラベルを決定する。
   - **タイトル**: 改修内容が一目でわかる日本語。30文字以内を目安とする。種別のプレフィックス（`feat:`など）は付けない。
   - **ラベル**: 以下の基準で1つ付与する。

   | ラベル | 用途 |
   | --- | --- |
   | `enhancement` | 機能追加・改善 |
   | `bug` | バグ修正 |
   | `documentation` | ドキュメントの追加・修正 |

4. Bashツールで`gh issue create`を実行する。本文はHEREDOCで渡す。

   ```bash
   gh issue create --title "{タイトル}" --label "{ラベル}" --body "$(cat <<'EOF'
   ## 背景

   {1〜2文}

   ## 改修内容

   - {1行}

   ## 完了条件

   - [ ] {1行}
   EOF
   )"
   ```

5. 作成されたIssueのURLと番号をユーザーに報告する。

## 記載ルール

- テンプレートのセクション構成（`## 背景` / `## 改修内容` / `## 完了条件`）と順序を変更しない。セクションの追加・削除もしない。
- テンプレート内のHTMLコメント（`<!-- -->`）は、指示を読み取った上で**本文には含めない**。
- 文章量は最低限に留める。
  - 背景: 1〜2文
  - 改修内容: 箇条書き3項目以内、各項目1行
  - 完了条件: 箇条書き3項目以内、各項目1行（`- [ ]`形式）
- 冗長な前置き・補足説明・所感は書かない。事実と決定事項のみを記載する。

## 注意事項

- Issueの作成のみを行う。ブランチ作成・実装には進まない（開発フロー全体は`.claude/rules/development-flow.md`を参照）。
- 同じ内容のIssueが既に存在しないか、`gh issue list`で確認してから作成する。
